## 1. 로그인 방법

AWS 실습 계정은 **AWS IAM Identity Center (SSO)** 를 통해 접속합니다.

### 1-1. 초기 비밀번호 설정

계정이 처음 생성되면 **이메일로 비밀번호 설정 링크가 발송**됩니다. 로그인 전에 반드시 먼저 진행하세요.

1. 등록된 이메일 받은편지함을 확인합니다.
2. **"Accept invitation"** 또는 **"비밀번호 설정"** 링크를 클릭합니다.
3. 원하는 비밀번호를 직접 설정합니다.

> 이메일이 오지 않거나 링크가 만료된 경우 관리자에게 문의하세요.

![비밀번호 변경 이메일](images/CleanShot%202026-05-20%20at%2017.12.26@2x.png)

### 1-2. 로그인 ID

로그인 ID는 **본인의 이름(영문)**입니다. 이름 형식에 주의하세요.

```
형식: {FirstName}{LastName}  (띄어쓰기 없이, 각 이름의 첫 글자는 대문자)
예시: KyuminKim
```

> **주의:** 대문자/소문자를 틀리거나 띄어쓰기를 입력하면 로그인이 되지 않습니다.

### 1-3. SSO 포털 접속

1. 관리자가 제공한 **SSO 로그인 URL**로 접속합니다.
2. 로그인 ID와 설정한 비밀번호를 입력합니다.
3. 로그인 후 실습용 AWS 계정을 선택하여 콘솔에 접속합니다.

- 세션은 로그인 후 **8시간** 동안 유지됩니다. 이후에는 재로그인이 필요합니다.

![콘솔 접속](images/CleanShot%202026-05-20%20at%2017.18.20@2x.png)

## 2. 사용 가능한 리전

실습 계정은 **서울 리전 (`ap-northeast-2`) 전용**입니다.

| 항목      | 내용                                  |
| --------- | ------------------------------------- |
| 허용 리전 | 아시아 태평양 (서울) `ap-northeast-2` |
| 차단 리전 | 서울을 제외한 **모든 리전**           |

> **주의:** AWS 콘솔 우측 상단의 리전을 서울로 설정하지 않으면 리소스가 보이지 않거나 작업이 차단될 수 있습니다.

![리전 확인](images/CleanShot%202026-05-20%20at%2017.21.23@2x.png)

## 3. 예산 및 비용 정책

각 학생에게는 **월 $40 USD** 의 예산이 부여됩니다.

| 사용 비율 | 조치                                            |
| --------- | ----------------------------------------------- |
| 50% 초과  | 관리자에게 경고 알림 발송                       |
| 80% 초과  | 관리자에게 경고 알림 발송                       |
| 100% 초과 | **킬 스위치 작동** → 실행 중인 리소스 자동 중지 |

- 예산은 **본인 소유 리소스(Owner 태그 기준)** 의 비용만 집계됩니다.
- 예산 초과 전에 불필요한 리소스를 반드시 **중지 또는 삭제**하세요.
- EC2 인스턴스를 사용하지 않을 때는 **Stop** 상태로 유지하면 비용을 절약할 수 있습니다.

## 4. EC2 제약 사항

### 4-1. 허용 인스턴스 타입

실습에서 생성할 수 있는 인스턴스 타입은 **t 계열 소형**으로 제한됩니다.

| 계열 | 허용 타입                            |
| ---- | ------------------------------------ |
| t2   | `t2.nano`, `t2.micro`, `t2.small`    |
| t3   | `t3.nano`, `t3.micro`, `t3.small`    |
| t3a  | `t3a.nano`, `t3a.micro`, `t3a.small` |
| t4g  | `t4g.nano`, `t4g.micro`, `t4g.small` |

> **차단 인스턴스 타입:** c, m, r, i, d, h, z, f, p, g, x 계열 등 고사양/고비용 타입은 **모두 차단**됩니다.

### 4-2. 인스턴스 생성 방법

인스턴스를 생성할 때 반드시 **Owner 태그**를 본인의 **표시 이름(Display Name)** 으로 설정해야 합니다.

```
태그 키:   Owner
태그 값:   본인의 표시 이름 (예: kyumin-kim)
```

> Owner 태그가 없거나 다른 값으로 설정하면 인스턴스 생성이 **거부**됩니다.  
> 표시 이름은 로그인 ID(`KyuminKim`)와 다릅니다. 소문자 하이픈 형식(`kyumin-kim`)을 사용하세요.

![EC2 태그 설정](images/CleanShot%202026-05-20%20at%2023.44.04@2x.png)

### 4-3. 가능한 EC2 작업

| 작업                           | 가능 여부 | 조건                                     |
| ------------------------------ | --------- | ---------------------------------------- |
| 인스턴스 조회 (전체)           | ✅ 가능   | -                                        |
| 인스턴스 생성                  | ✅ 가능   | Owner 태그 = 본인 표시 이름, 허용 타입만 |
| 인스턴스 시작/중지/재부팅/삭제 | ✅ 가능   | 본인 소유 인스턴스만                     |
| 키 페어 생성/삭제/가져오기     | ✅ 가능   | -                                        |
| 보안 그룹 생성                 | ✅ 가능   | -                                        |
| 보안 그룹 규칙 관리            | ✅ 가능   | 본인이 만든 보안 그룹만                  |
| 탄력적 IP 할당/해제/연결       | ✅ 가능   | Owner 태그 = 본인 표시 이름              |
| 타인 인스턴스 조작             | ❌ 불가   | -                                        |
| 고비용 인스턴스 타입 생성      | ❌ 불가   | -                                        |

## 5. S3 제약 사항

### 5-1. 버킷 명명 규칙

본인이 만드는 모든 S3 버킷 이름은 반드시 **본인의 표시 이름(Display Name)으로 시작**해야 합니다.

```
형식: {표시이름}-{원하는이름}
예시: kyumin-kim-my-bucket
      kyumin-kim-lab-data
      kyumin-kim-static-site
```

> 다른 이름으로 버킷을 생성하면 **거부**됩니다.

![버킷 이름 설정](images/CleanShot%202026-05-20%20at%2023.47.26@2x.png)

### 5-2. 가능한 S3 작업

| 작업                         | 가능 여부 | 조건                                  |
| ---------------------------- | --------- | ------------------------------------- |
| 전체 버킷 목록 조회          | ✅ 가능   | -                                     |
| 버킷 생성/삭제               | ✅ 가능   | 이름이 본인 표시 이름으로 시작해야 함 |
| 버킷 정책, 태그, 암호화 설정 | ✅ 가능   | 본인 버킷만                           |
| 객체 업로드/다운로드/삭제    | ✅ 가능   | 본인 버킷만                           |
| 타인 버킷 접근               | ❌ 불가   | -                                     |

## 6. RDS 제약 사항

### 6-1. 허용 인스턴스 타입

| 허용 타입      |
| -------------- |
| `db.t3.micro`  |
| `db.t4g.micro` |

> `db.m`, `db.r`, `db.x`, `db.z`, `db.p` 등 고성능 타입은 **모두 차단**됩니다.

> **주의:** 가용성 및 내구성 설정(Multi-AZ 등)에 따라 버스터블 클래스(t 클래스)가 지원되지 않는 경우가 있습니다. 이 경우 지원되는 설정으로 변경하세요.

![RDS 허용 타입](images/CleanShot%202026-05-21%20at%2000.05.43@2x.png)

### 6-2. 자격 증명 관리

RDS 인스턴스 생성 시 **자격 증명 관리(Credential management)** 를 반드시 **자체 관리(Self managed)** 로 설정하세요.

> Secrets Manager를 선택하면 별도 비용이 발생하여 예산에 영향을 줍니다.

![자격 증명 관리](images/CleanShot%202026-05-21%20at%2000.02.28@2x.png)

### 6-3. Aurora 클러스터 사용 불가

Aurora DB 클러스터(`CreateDBCluster`) 생성은 **전면 차단**됩니다.  
단일 RDS 인스턴스만 사용 가능합니다.

![Aurora 사용 불가](images/CleanShot%202026-05-20%20at%2023.54.47@2x.png)

### 6-4. 인스턴스 생성 방법

EC2와 동일하게 **Owner 태그**를 본인의 **표시 이름(Display Name)** 으로 설정해야 합니다.

```
태그 키:   Owner
태그 값:   본인의 표시 이름 (예: kyumin-kim)
```

![RDS 태그 설정](images/CleanShot%202026-05-20%20at%2023.59.45@2x.png)

### 6-5. 가능한 RDS 작업

| 작업                      | 가능 여부 | 조건                                     |
| ------------------------- | --------- | ---------------------------------------- |
| DB 인스턴스 조회 (전체)   | ✅ 가능   | -                                        |
| DB 인스턴스 생성          | ✅ 가능   | Owner 태그 = 본인 표시 이름, 허용 타입만 |
| DB 시작/중지/재부팅/삭제  | ✅ 가능   | 본인 소유 DB만                           |
| DB 스냅샷 생성/삭제/복사  | ✅ 가능   | 본인 소유 DB만                           |
| 스냅샷으로 복원           | ✅ 가능   | -                                        |
| Aurora 클러스터 생성      | ❌ 불가   | -                                        |
| 고비용 인스턴스 타입 사용 | ❌ 불가   | -                                        |
| 타인 DB 조작              | ❌ 불가   | -                                        |

## 7. 리소스 격리 정책

실습 환경은 **ABAC (Attribute-Based Access Control)** 방식으로 학생 간 리소스를 격리합니다.

- 모든 리소스에는 `Owner` 태그로 소유자가 기록됩니다.
- **본인이 만든 리소스만 수정/삭제**할 수 있습니다.
- 다른 학생의 리소스는 조회만 가능하고, 수정/삭제는 불가합니다.

> 실수로 타인의 리소스를 건드리지 않도록 주의하세요. 작업 전 리소스의 Owner 태그를 확인하는 습관을 들이세요.

## 8. 킬 스위치 (자동 차단)

예산 100%를 초과하면 **킬 스위치 Lambda 함수**가 자동으로 실행됩니다.

### 킬 스위치 작동 시 발생하는 일

| 서비스        | 조치 내용                               |
| ------------- | --------------------------------------- |
| EC2           | 본인 소유 인스턴스 **자동 중지**        |
| EC2 탄력적 IP | 연결 해제 및 **반환**                   |
| S3            | 퍼블릭 액세스 차단 설정, Deny 정책 적용 |
| RDS           | 본인 소유 DB 인스턴스 **자동 중지**     |

> 킬 스위치가 작동하면 관리자에게 연락하세요. 실습 재개를 위한 조치를 안내해 드립니다.

### 킬 스위치 예방 방법

1. 사용하지 않는 EC2/RDS는 **즉시 중지(Stop)** 하세요.
2. 실습이 완료된 리소스는 **삭제(Terminate/Delete)** 하세요.
3. AWS 콘솔 상단 **Billing** 메뉴에서 현재 비용을 주기적으로 확인하세요.
4. 탄력적 IP(EIP)는 인스턴스에 연결되지 않아도 비용이 발생합니다. 미사용 EIP는 **즉시 해제**하세요.

## 9. 자주 묻는 질문

**Q. 인스턴스를 생성하려는데 "권한 없음" 오류가 납니다.**  
A. 다음을 확인해 주세요.

- 리전이 **서울(ap-northeast-2)** 로 설정되어 있는지 확인하세요.
- 인스턴스 타입이 허용 목록(t2/t3/t3a/t4g 소형)에 있는지 확인하세요.
- 태그에 `Owner = 본인 표시 이름` 이 정확히 입력되었는지 확인하세요. (예: `kyumin-kim`)

**Q. S3 버킷을 만들었는데 접근이 안 됩니다.**  
A. 버킷 이름이 본인의 표시 이름으로 시작하는지 확인하세요. (예: `kyumin-kim-버킷이름`)

**Q. 다른 학생의 EC2 인스턴스가 보이는데 접속할 수 있나요?**  
A. 조회는 가능하지만 시작/중지/삭제 등 조작은 불가합니다. 다른 학생의 리소스를 건드리지 마세요.

**Q. RDS Aurora를 사용하고 싶습니다.**  
A. 비용 관리를 위해 Aurora 클러스터는 차단되어 있습니다. 단일 RDS 인스턴스를 사용해 주세요.

**Q. 예산이 초과되어 킬 스위치가 작동했습니다.**  
A. 관리자에게 즉시 연락하세요. 상황을 확인 후 실습 재개를 도와드립니다.
